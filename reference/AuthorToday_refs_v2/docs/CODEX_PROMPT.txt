ЦЕЛЬ ТЕКУЩЕЙ ИТЕРАЦИИ:
1. Создать недостающий раздел «Моя библиотека», добавить пункт в боковое меню. Состояния книг: «Читаю», «Прочту позже», «Прочитано», «Не интересно». Выбор статуса — модальное окно поверх карточки. При «Не интересно» убрать книгу из обычной выдачи, но обеспечить доступ к ней на соответствующей полке библиотеки для возврата.
2. Исправить сохранение: полка книги и прогресс чтения должны сохраняться после переходов, F5 и перезапуска приложения. Хранить хотя бы ID книги, ID главы, позицию/процент, lastReadAt. На главной блок «Вы читали» должен показывать действительно последнюю книгу и актуальный прогресс, не фиксированное 24%. Использовать AsyncStorage (или существующий переносимый механизм) без затирания состояния моковыми значениями на старте.
3. Добавить «Настройки», доступные из бокового меню, с переключателем «Имитация отсутствия интернета». Это искусственное состояние mock API — НЕ пытаться выключить физическую сеть ПК/Android! Сеть OFF: сетезависимые мок-запросы возвращают offline, выводится экран из новых референсов с текстом «Нет подключения к интернету» и кнопкой «ОБНОВИТЬ». В offline должны оставаться доступны «Последние книги» и локальная библиотека/кешированные главы. Сеть ON: кнопка «ОБНОВИТЬ» должна повторно запросить данные, показать loading и вернуть выдачу. Учесть отдельные empty/error состояния.
4. Исправить поиск и подбор: два НЕЗАВИСИМЫХ сценария («ИЛИ» на оригинале). Текстовый поиск по книгам/авторам/постам не должен случайно использовать старые фильтры каталога. Подбор — пересечение всех условий через AND, включая ТОЛЬКО книги со ВСЕМИ выбранными включёнными жанрами; исключённые жанры не допускаются вообще. Приведи значения жанров и форматов к согласованным ключам, чтобы не возникало ложных нулевых результатов. Отсутствие фильтров означает каталог без ограничения, а не пустую выдачу. Сортировка — после фильтрации.
5. Довести обязательные кнопки, навигацию и оверлеи, провести проверку взаимодействий. Дополнить существующий второй сценарий: результаты поиска людей → профиль автора; вкладки «Произведения», «Блог», «Иллюстрации» ориентировать на новые оригинальные скриншоты, но не в ущерб первичным четырём задачам.

ПРОЦЕСС РАБОТЫ:
- Сначала изучи текущие файлы и подготовь компактный аудит: что уже реализовано, какие именно файлы менять, что отсутствует, где искать ошибку «всегда найдено 0 книг».
- Реализовывай по очереди: (A) постоянное состояние и «Моя библиотека»; (B) настройки/эмуляция offline; (C) фильтрация/поиск + loading/empty/retry; (D) кнопки и доработка автора. После каждой группы проверь сценарии из `ACCEPTANCE_CHECKLIST.md`.
- Используй текущие зависимости. Если потребуется новое хранилище, установи совместимую Expo-версию `@react-native-async-storage/async-storage` через `npx expo install`.
- Не меняй существующий mock kit без необходимости, подключай его через адаптеры, переиспользуй компоненты. Не делай реальных запросов к Author.Today.
- Не ломай кроссплатформенность: на Web сейчас проверяем, но реализация должна работать в Android. Не используй прямые браузерные API в общих компонентах без адаптера.
- Сохраняй существующую работу пользователя, не делай массовый рефакторинг без необходимости, не удаляй имеющиеся референсы.
- НЕ делай git commit/push и не создавай pull request без отдельного указания пользователя.
