# Функциональные требования к следующей итерации

## A. Поиск и подбор — ДВА независимых пути

**Текстовый поиск**: ввод названия/имени автора/текста поста → кнопка/Enter → отдельные группы результатов «Люди», «Книги», «Посты» (где есть совпадения). Выбор пользователя открывает профиль автора, выбор книги — карточку книги. Не переносить в текстовый поиск старые выбранные фильтры, если оригинал явно отделяет поиск от подбора («ИЛИ»).

**Подбор по интересам**: параметры жанров, исключённых жанров, формата, сортировки и доп. фильтров → «ПОДОБРАТЬ» → список книг. Применять AND **между всеми условиями**. Для нескольких включённых жанров требовать `selectedGenres.every(g => book.genres.includes(g))`, а не `some`. Для исключённых жанров книга проходит только если `!excludedGenres.some(g => book.genres.includes(g))`. Данные должны использовать согласованный справочник жанров (лучше id, не свободно набранные названия), чтобы не возникало ложного «0 результатов» из-за разного написания «Темное»/«Тёмное».

Пустой массив фильтров означает «нет ограничения», а не «ничего не подходит».

Не путать AND между группами фильтров с выбором значения в одном одноэлементном радио-поле (например, «Статус: завершено/в процессе»). Сортировка применяется ПОСЛЕ фильтрации.

Если нет результатов, показывать оригинальное состояние «К сожалению, по вашему запросу ничего не найдено» с подходящей иллюстрацией из локальных материалов, если она доступна как самостоятельный файл, а не обрезанный скриншот. Можно оформить похожую иллюстрацию в UI; **не вставлять целый скриншот как экран**.

## B. Библиотека и сохранение чтения

Создать «Моя библиотека», доступную через пункт бокового меню (гамбургер) и при необходимости кнопку «В БИБЛИОТЕКУ» на офлайн-экране. Полки: «Читаю», «Прочту позже», «Прочитано», «Не интересно». В карточке книги «В библиотеку» открывает модальное окно выбора статуса; выбранное значение отображается в карточке и сохраняется. «Не интересно» — исключить книгу из обычных поисковых результатов/подбора; разрешить увидеть и изменить статус из библиотеки. Статусы должны сохраняться после перезагрузки вкладки браузера и перезапуска Android приложения.

Прогресс чтения: хранить `bookId`, `chapterId`, позицию внутри главы (или стабильный scroll offset / процент), `updatedAt` и `lastReadAt`. При «Читать» у сохранённой книги возвращаться к текущей главе и позиции, а не всегда открывать первую. На главной «Вы читали» показывать последнюю читаемую книгу и реальный процент; в библиотеке тоже показывать прогресс.

Использовать проектное постоянное хранилище: `@react-native-async-storage/async-storage` через `npx expo install`, либо уже существующий аналог. Для Expo Web обеспечить работающий адаптер; если работает браузерная версия, проверить после F5. Не хранить данные только в `useState`.

Учесть инициализацию: не затирать сохранённое значение дефолтными мок-статусами при каждом запуске. Сначала загрузить сохранённое, если его ещё нет — инициализировать один раз. Не изменять исходный mock kit ради сохранения пользователя.

## C. Настройки / симуляция сети

Добавить в боковое меню пункт «Настройки». На отдельном экране (или в панели) показать видимый переключатель **«Имитация отсутствия интернета»** со статусом «Сеть включена / Сеть отключена». Это только состояние нашего приложения, оно НЕ отключает физическую сеть Windows, браузера или Android.

Когда имитация включена, сетезависимые методы mock API (получение актуальной выдачи, поиск, обновление и профиль автора если не кеширован) должны выдавать понятную ошибку offline; показать экран как в `original/06_offline_error.png`, с кнопкой «ОБНОВИТЬ». «ОБНОВИТЬ» при отключении снова показывает offline; после включения сети — повторяет реальный mock-запрос, выводя loading и результат. Для демо сетевой статус можно сохранять на время сессии; после перезагрузки браузера предпочтительно сохранять его тоже, чтобы тест был повторяемым.

Локальная библиотека и ранее подготовленные/кешированные главы должны оставаться доступными в offline. На офлайн-экране покажите карусель «Последние книги» и кнопку «В БИБЛИОТЕКУ» в духе оригинального экрана. Можно кешировать весь учебный текст глав: настоящих сетевых запросов к Author.Today нет.

Кроме offline, оставить независимые режимы тестирования `loading`, `empty`, `generic error` (например, через флаги в mock API / dev-настройки). Никаких ложных успехов при ошибке.

## D. Навигация и интерфейс

Убедиться, что все основные кнопки работают: главная → поиск/подбор → результаты → книга → выбор статуса → чтение → настройки читалки, плюс текстовый поиск → люди → профиль автора и путь в библиотеку. Любая видимая кнопка в обязательном сценарии должна иметь ожидаемое действие. Проверить закрытие оверлеев, обработку Back, возврат к списку, сохранение фильтров и прокрутки при необходимости.

Придерживаться React Native компонентов, запускать через Expo Web без HTML-зависимой логики для основных экранов. Не ломать Android совместимость. Для визуальной точности сверять с оригинальными скриншотами, но не вставлять цельные скриншоты вместо реализации.

Работать итерациями: 1) сохранение + библиотека, 2) настройки + offline, 3) поиск/фильтры/пустая выдача, 4) профиль автора/кнопки и визуальная доводка. После каждой итерации тестировать. Не менять удачный текущий главной экран без причин.
