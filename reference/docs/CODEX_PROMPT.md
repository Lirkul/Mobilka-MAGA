# Промпт для Codex — продолжение разработки Author.Today

Продолжаем существующий учебный проект клона Author.Today (Android, оригинал 1.9.005-GMS) на React Native + Expo + JavaScript. Дизайн главного экрана уже реализован и визуально устраивает — **не переписывай и не ломай его**. Сейчас тестируем через Expo Web, итог — Android APK.

Уже есть репозиторий GitHub и ветка `develop`. Скриншоты оригинала и схема переходов лежат в `reference/`, а новые учебные мок-данные в `reference/AuthorToday_mock_kit/`.

## Задача

1. Сначала **прочитай текущий исходный код и структуру проекта**, особенно реализацию главной, поиска, фильтров и существующий формат данных. Не предполагая имена компонентов заранее, выясни, как организованы их свойства и состояние.
2. Изучи `reference/AuthorToday_mock_kit/README.md`, `docs/INTEGRATION.md`, `src/data`, `src/utils/filterBooks.js`, `src/services/mockApi.js` и каталог `assets`.
3. Интегрируй 20 фиктивных книг, 8 авторов, 120 глав, 60 комментариев, 4 поста и 3 цикла в проект. Скопируй изображения из учебного архива в `assets/mock-covers` и `assets/mock-avatars`, а данные и сервисы в `src/`. Сохрани исходные реальные скриншоты только как референсы. Новые изображения показывай в списке книг, карточке книги и профилях авторов; не подменяй целые экраны скриншотами.
4. **В первую очередь исправь фильтрацию**. Если пользователь выбрал несколько жанров, то книга должна содержать **каждый** из них (`every()`, AND), а не хотя бы один (`some()`, OR). Аналогично для выбранных тегов. Все заполненные поля фильтрации объединяются через AND. `excludedGenres` означает, что ни один запрещённый жанр не встречается в книге. Радио-поля (`status`, `format`, `access`, сортировка) остаются одиночными значениями, не массивами.
5. Проверь точность конкретного примера: `genres=['Темное фэнтези','Боевая фантастика']`, `status='ongoing'`, `access='free'` должны выдать среди новых фикстур **строго `book_001` и `book_019`**. Книги с одним из выбранных жанров не должны появляться.
6. Подключи данные к существующим UI-компонентам без регрессий дизайна. Если текущие компоненты используют другие поля (`author`, `cover`, `price`, `type`), сделай небольшой адаптер данных на границе UI, а не правь весь интерфейс.
7. Подбор через фильтры и текстовый поиск **разные сценарии**. Текстовый поиск должен находить книги, авторов и посты через `searchAll`; выбор из выдачи приводит на соответствующий экран. Фильтры подбора — только на книги через `getBooks`.
8. При нажатии «В библиотеку» показывай **модальное окно поверх карточки** с 4 вариантами: «Читаю», «Прочту позже», «Прочитано», «Не интересно». После выбора обновляй состояние книги. «Не интересно» скрывает книгу из последующей выдачи; `setLibraryStatus` уже поддерживает это.
9. Сохрани переход «Карточка книги → Читать → Читалка». Используй `getChapters` и `getChapter` для отображения текста, `saveReadingProgress` для положения чтения. **Не используй чужие реальные фрагменты произведений**: тексты в фикстурах выдуманы.
10. Сначала полностью интегрируй слой данных и фильтров, затем по одной части UI: результаты → карточка → поиск авторов → чтение. Не переписывай весь проект одним большим изменением.

## Условия реализации

- Используй React Native-компоненты и `StyleSheet`, без HTML/CSS и без зависимости от браузера: приложение должно собраться для Android.
- Внешний вид соответствует скриншотам оригинала; новые обложки нужны **для содержимого**, а не для изменения дизайн-системы.
- Metro требует **статических `require()`** изображений; готовый файл `src/data/imageSources.js` содержит нужную карту.
- Не трогай `.gitignore`, `reference/screenshots` и другие данные без необходимости. Не удаляй существующий код и не перезаписывай работающие экраны без согласования.
- Никаких настоящих HTTP-запросов к Author.Today или платежей.
- `mockApiControl` позволяет имитировать загрузку и ошибку сервера для ДЗ3. Если сохраняешь состояние между запусками, подключи AsyncStorage отдельно, объяснив зачем он нужен.
- Не делай `git push`, `force`, `reset --hard`, `rebase` и не создавай PR без моего разрешения. Показывай изменения для проверки.

## Проверка

1. `node --test reference/AuthorToday_mock_kit/tests/filterBooks.test.mjs` — все тесты должны проходить.
2. `npx.cmd expo start --web` — приложение открывается и главная не сломана.
3. Несколько выбранных жанров сужают выдачу, а не расширяют.
4. В выдаче видно несколько разных новых обложек и авторов.
5. Поиск по книге и автору работает, по пустому запросу нет ошибки.
6. Добавление книги с «Читаю» обновляет карточку; «Не интересно» скрывает книгу из каталога.
7. Читалка открывает текст главы, можно перейти к другой главе.

**Начни с аудита существующего проекта и краткого плана интеграции. После этого приступай к первому небольшому изменению: интеграция мок-данных и исправление фильтров. Объясни, какие файлы изменены и как проверить результат.**
